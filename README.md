# dsh-client-ui-durandal · 幽兰黛尔皮肤 v2.0

DeepSeek Harness Web GUI 的客户端皮肤：以《崩坏3》幽兰黛尔（比安卡·阿塔吉娜）"圣痕礼装"为主题。

**立绘即界面**——新会话里画面上只有立绘和底部一张浮空输入卡，没有别的；对话区内**思考与工具调用过程完全通透**，文字直接压在立绘上（靠发丝级文字光晕保证轮廓），**只有你的提问和助手的正文各坐一块实底**，因为那两处是要回头读的。侧栏是一块**浅色羊皮纸**；**设置、弹窗、菜单保持实底**，因为那些界面要拿来用。

## 安装 / 卸载

```bash
node tools/build.mjs      # 内联立绘，生成 lib/client.js
node tools/verify.mjs     # 全部门禁：安全 lint + 假 DOM 冒烟 + 设计断言 + 打包断言（0 失败才放行）
node tools/install.mjs    # 装进 desktop profile（幂等、自动备份）
# 然后重启 DeepSeek Harness
node tools/uninstall.mjs  # 彻底卸载
```

`desktop` profile 由 Electron 独占，`dsh plugin --profile desktop add` 会被 CLI 拒绝，因此 `install.mjs` 手工完成等价三步：复制到 `$DSH_HOME/plugins/dsh-client-ui-durandal`（**只装运行产物**：`lib/`、`package.json`、`cordis.patch.yml`、`README.md`）→ 写入 profile 依赖并建立 `node_modules` 链接 → 把包名加进 profile 的 `dsh.profile.bundles`（先备份）。

**它是一个组合包（bundle），不是一个裸依赖**。`package.json` 声明 `dsh.bundle.patch: "./cordis.patch.yml"`，app-boot 在组合 loader 树时按 `dsh.profile.bundles` 的顺序逐个应用每个组合包自己的补丁层，所以**插入 loader 条目的是包自带的 `cordis.patch.yml`**，profile 只负责"选中"它。这个区别是可观察的：应用侧栏的**插件**页把 profile 的**组合包**列在**已安装**分组下——只装进 `node_modules` 而没被选中的依赖**有意不列出**。所以旧版把 `- insert:` 手写进 profile patch 的做法既进不了插件页，又会在迁到 bundle 后重复插入同一 id；`install.mjs` 会先清掉那段遗留块再选中组合包。

**入口 id 的硬性约定**：宿主把 bundle 挂在 `/plugins/<entry id>/client.js`，随后要求 bundle 注册同一个 id，因此
`cordis.patch.yml` 的 `id` ＝ `__ModuleLoader__.load({ id })` ＝ `package.json` 的 `name`（`verify.mjs` 会校验）。

## 使用

**设置 → 幽兰黛尔**：

| 控件 | 作用 |
| --- | --- |
| 立绘优先 | 一键：背景 4%、不虚化，界面最透 |
| 启用皮肤 | 总开关；关闭即还原原生界面（快捷键 `Ctrl+Alt+Shift+D`） |
| 对话背景 | 立绘 / 纯净（纯净模式自动把底色改为不透明，不会透出窗口） |
| 背景明暗 | 0–90%，默认 0；**这是唯一还会压暗立绘的东西**——底下不再垫任何恒定薄膜，0 就是素材文件的原始亮度 |
| 背景模糊 | 0–24px，只作用于壁纸图层 |
| 展示模式 / 正文虚化 | 默认关闭；开启后指针离开正文时正文淡出（纯 CSS `:hover`/`:focus-within`） |
| 描边细节 | 选中态色块、代码块描边、聚焦边（浅色蓝 / 深色金） |

控制台：`window.durandalSkin.artFirst()` / `enable()` / `disable()` / `set("veil", 20)` / `status()` / `reset()`。

## 设计

- **配色**：她本人的白 / 蓝 / 金，收敛成**一条硬规则——浅色读蓝，深色读金**，并且它覆盖**三族**而不只是描边：
  - **描边与纹样**：浅色**深冷蓝**（发丝线 `rgba(104,124,180,·)`、纹样线 `#687CB4`、主菱 `#5C72AE`），深色礼装金 `#D9AE45` / `#F0D691`。亮金在白底上等于看不见，所以浅色一律走冷色同族；色相与浓淡都按"发丝线要在亮屏上立得住"调过——更早的 `#8C9BC4` 太浅，在亮屏上几乎消失。这条已由 `verify.mjs` 断言（够冷 **且** 够浓，不写死字面量）。
  - **墨色梯度**：浅色是冷 navy 阶梯（`#111A2E` → `#525F80`），深色就必须是**同阶梯的香槟色**（`#F1E7D2` → `#B49C78`）。这一族曾经只有 primary 是暖的、其余全是冷蓝灰，于是输入框的占位文字与次级标签在深色下读起来是蓝的。
  - **行动与强调色**：品牌主色、主按钮、**输入框发送按钮**（`--dsw-alias-button-info-fill`，长期未被覆盖）、光标与待发送圆点（`--dsw-alias-state-business-primary`）、焦点环、滚动条、正文引用链接、面板控件 —— 浅色皇家蓝 `#2F5FD0`，深色礼装金。
  - **有意不参与对应**（它们没有"金"这个对应物）：语义色（警告琥珀 / 成功绿 / 错误红——金色警告不成其为警告）、近黑的**反白墨**与实底填充（`#101828`、`rgba(16,24,42,.88)`，亮度 ≈ 0.09）、以及中性半透明白（控件瓷砖、镶边伴随线）。
  - 浅色模式下 `bg-base` 也**完全透明**（立绘原样到场，见下节"零薄膜"），所有高层级表面都是**纯白实底**；深色是全海军蓝夜。
- **侧栏**：纯白半透面板（皮肤自有变量 `--sk-panel`）+ 右缘**四层镶边**（发丝线 + 一道白伴随线 + 强调线 + 柔和内线，全部内嵌 box-shadow，不占布局）。
- **"新会话"是一枚礼装横幅**，不是圆角矩形：两端斜切成尖角（`clip-path` 六边形轮廓），字距略开，内嵌一道同形线框。**浅色填充皇家蓝渐变**（`#5480E8 → #3A69DC → #2C5ACB`，白字）；**深色填充礼装金渐变**（`#FFF6CE → #FBE7A0 → #F2D264`，深墨字，蓝色瓷砖会和海军蓝+金的侧栏打架）。
- **装饰**——全部是**方案感知**的皮肤令牌（浅色蓝 / 深色金），装饰层不参与命中。一条总原则：**只在边缘和实底表面装饰，绝不横跨正文**（这套皮肤的前提是"立绘即界面"；对话区的**过程区**完全通透，只有提问与正文两块实底）。这句话写进 CSS 时有个陷阱：**过程区的每一行本身也是 `assistant-step`**——"给 assistant-step 上实底"会连思考行、工具间歇的叙述行一起上，于是折叠起来的过程区变成一列**空底小条**叠成的大色块（见"安全不变量"第 8 条）。实底只能按 `data-turn-process-member` 排除，不能按 kind：
  - **侧栏**：**骑士纹章水印**（`--sk-crest`，内联 SVG，156px）+ **"线—菱—线"分隔饰**（`--sk-divider`，宽 62%）+ 面板一层**斜向光泽**（`--sk-panel-sheen`）。纹章的两个变体由**同一个模板函数**生成（早先用字符串 split 从蓝变体"推"出金变体，而 split 找的字面量源码里根本没有，于是两个方案发的是同一枚暖金纹章）。
  - **铭牌**（`--sk-inscription`）：`BIANKA ATAEGINA ◆ DURANDAL`，18×472px、字号 14.5 / 字重 600，逐字母叠排，两端各一枚菱形端标、中间一枚分隔菱（与内嵌饰带、行标、分隔饰同一母题）。**挂在对话列左侧空白带而不是侧栏**——背景图层永远画在面板内容之下，挂在侧栏时会话行会直接把字母盖住（`verify.mjs` 现在断言它的宿主，防止被改回去）。**做成 SVG 背景图层而不是定位伪元素**：应用的侧栏与对话列规则都**没有 `position`**（即 `static`），绝对定位的伪元素没有可锚定的包含块，两栏又都 `overflow:hidden`（顺带绕开"伪元素必须 `pointer-events:none`"这条 lint）。字体用系统衬线体栈：SVG 作为图像渲染时读不到宿主的 `@font-face`，平台的 Montserrat 在此不可用——铭牌本就更适合衬线罗马大写。
  - **对话列**（`_centerCol`）：镜像同一道镶边 + 左缘铭牌 + 右缘 `--sk-inlay` 竖向饰带，两栏因此读成一整幅裱框。
  - **输入卡片**（`[data-composer-card]`）：顶边正中央一枚**印章线**（中段加厚成实体、两侧渐隐，180×3px）+ 四角 20px 角标。之所以能绝对定位，是因为应用自己的卡片规则是 `position:relative` 且未占用 `::before`。
  - **设置面板**（皮肤自有，`.sk-*`）：头部一道渐隐分隔线、标题前一枚金菱、每张卡片四角 18px 角标。
  - 发丝线 `--sk-edge`、强调线 `--sk-accent-line`、柔和线 `--sk-edge-soft` 组成侧栏那道四层镶边；控件瓷砖用 `--sk-tile` / `--sk-tile-hover`（深色下退为淡白雾，硬编码的白瓦片在深色下像贴上去的）。
- **深色模式下侧栏所有文字都改用礼装金**（`#F0D691` / `#E8C56A` 家族）：`applyVars()` 在 `<html>` 上盖 `data-sk-scheme` 属性，CSS 用 `[data-sk-scheme="dark"] [class*="_sidebarCol"]` 做**列级**令牌重绑定（`!important` 才能压过 `body` 上的内联令牌）；横幅自己的按钮级重绑定优先级更高，所以"新会话"仍是深墨字。
- 图标按钮是浅瓷砖；构建徽标与品牌芯片是小块**深底瓷砖**（保证任何面板上都可读），字色随方案走冷蓝 / 礼装金。整套只保留两种交互提示（悬停＝发丝描边，选中＝左脊 + 色块）。
- **立绘**：面板居中于"侧栏右侧的对话列"，高 1330px；人物经过饱和度遮罩增强（只提彩色像素），底场由同一张图模糊而来，因此没有拼接缝，也不会出现"脏"的色调断层。

## 空状态与输入区

新会话是唯一"立绘可以独占画面"的时刻，而应用原本把它填满了：中间是官方的 **hero 空态**（鲸鱼图标 +「探索未至之境」+「预览版」徽章，来自 `@deepseek-ai/dsh-client-ui-conversation`，**不是** `ui-chat`），输入框居中悬在它下面。现在：

- **空态整块消失**。hero 相位下输入框栈的子节点顺序恰好是 `[HeroShell, 工作区行, dock?, 输入框]`，所以按 **`:first-child`** 位置命中，而不是去匹配 `Hqq-bq_root` 那串每次构建都会变的哈希类名。必须隐藏**整个根节点**而不是只藏标题：`HeroShell` 的根是 `height:100%`，只藏文字会留下一个撑满栈的空块。
- **输入框沉到底部**，且仍然是那张浮空卡片（应用只在 `active` 相位给它加渐变垫底，hero 相位不加，所以"不给它实底"正是要的效果；`verify.mjs` 断言这一条，防止它退化成底部实底栏）。
- **沉底的机制是 `margin-top:auto`，不是 `position:sticky`**。sticky 只阻止盒子滚出容器顶部，**永远不会把盒子往下推**；配上 `justify-content:flex-start` 它会把卡片停到**最上面**。flex 里 auto 外边距先吃掉全部剩余空间，所以无论应用自己的 `justify-content` 说什么，卡片都会落到底部。这条也由 `verify.mjs` 反向锁死（断言**不得**出现 sticky）。
- **只有提问与正文有实底**（`--sk-flow-solid`）：提问的实底挂在**气泡**上（气泡自带应用的圆角与内边距，且贴合文字；挂在流条目上会得到一条通栏色带），正文的实底挂在**流条目**上并自带圆角与内边距。
  - 正文用 `assistant-step` **和** `[data-turn-process-answer]` 两个锚点：后者只在**思考折叠收起**时渲染（`compactAnswer && !processOpen`），只认它的话，读者一展开折叠、正文的底色就没了。
  - 实底规则必须**压过**那条通栏透明规则，而不是排在它后面：透明规则同时匹配 `[data-chat-flow-kind]`、`[data-chat-anchor-key]`、`[data-turn-process-answer]`，而这三个属性就在流条目**同一个元素**上，同特异性下后写的也赢不了。多一层 `[data-conversation-content]` 祖先才换来那一档权重。
  - 正文卡片加圆角与内边距，是**本皮肤唯一一处刻意在对话流里吃掉布局空间**（旧原则是"装饰不占位"）。`:not(:empty)` 是护栏：应用会把空的流条目塌成 `height:0`，24px 的上下内边距会把它悄悄撑成一条可见色条。
  - 有实底的行同时收掉文字光晕（`text-shadow:none`）——光晕是为了把字从立绘上拎出来，那两处下面已经没有立绘了。
- **这一段静态门禁验不了**：`verify.mjs` 的假 DOM 不渲染应用，所以上面这些只能靠实机（CDP 截图 + 采样像素）确认，`verify` 全绿是必要而非充分。

## 零薄膜

立绘上曾经叠着三层没人主动选择的膜，现在全部去掉了：

| 层 | 原来 | 现在 |
| --- | --- | --- |
| `html::after` 恒定洗白 / 洗黑 | `.12` / `.05` | 0（只留滑块项） |
| `--dsw-alias-bg-base`（对话区那张半透明"桌子"） | `0.08 + v·0.50` | `v·0.50` |
| `--dsw-specific-sidebar-fill`（Windows 整扇窗框） | `0.26` / `0.30` | 0 |

浅色下三者叠加约 40% 白、深色约 38% 海军蓝——每一层单独看都算"薄"，加起来就不薄了。**背景明暗滑块仍是唯一的压暗手段**（`verify.mjs` 两头都断言：veil 0 时不许留任何膜，veil 40 时必须能加上）。

代价（知情接受）：`bg-base` 归零后，`active` 相位输入框上方那条 36px 渐隐垫底失效，消息滚到底部是硬切而非淡出。因为输入卡片本身不透明（0.78–0.96），可以接受。

**素材一行没动**：`durandal-dark.jpg` 由 `../tools/make-art.py` 合成，里面 `grade_dark_panel` 把人物压在 88% 亮度并往海军蓝拉、边缘还有一道压暗带——那都是刻意的"夜场打光"。源图仍在，这条路留作后备：先摘膜实测，不够亮再回去调那两个参数。

## 变量与配色方案（一条硬规则）

| 类别 | 写在哪 | 谁来决定明暗 |
| --- | --- | --- |
| 颜色、面板、光晕、纹章、艺术图 URL | `ctx.theme.overrideTokens()` 的 `{light,dark}` **令牌对** | **DSH 自己**：presenter 把当前方案的值写成 `body` 的内联样式 |
| 壁纸的两个 URL | `applyVars()` 写在 **`<html>`** | CSS 用 `:has(body[data-ds-dark-theme])` 二选一 |
| 偏好数值（遮罩 α、模糊、立绘不透明度、虚化） | `applyVars()` 写在 `<html>` | 与方案无关的纯数字 |

**为什么壁纸必须在 `<html>`**：令牌落在 `body` 上，而壁纸层是 `html::before`——它不是 `body` 的后代，**读不到 body 的自定义属性**。这条是用 mock 探针抓出来的（`artLayer: "none"`）。

**为什么皮肤里不允许出现"猜明暗"的 JS**：早期版本用 `isDark()`（先读主题快照）来决定遮罩/面板/文字颜色，浅色模式下误判成深色，于是 **整个窗口被深色遮罩盖住**（实测侧栏 `rgb(88,93,106)`）。现在 `applyVars()` 只写数字，颜色一律交给令牌与 `:has()`，CSS 与应用不可能再各说各话。

**会话列表不是侧栏插件画的**：它由 `@deepseek-ai/dsh-client-ui-workspace` 渲染，类名是 `_sessionRow` / `_title` / `_projectRow` / `_sectionLabel`，而且**选中行走的是 `--dsw-alias-link`（蓝色）**——只重绑定侧栏的 label 令牌不会让会话名变色。所以深色下除了重绑定令牌，还把真实类名逐一点名并强制 `color`。

**侧栏活动会话行**另有 DSH 的三个令牌，也必须一起覆盖：
`--dsw-specific-sidebar-nav-item-active`（底色）、`-active-accent`（文字色）、`-hover`。深色下它们是"深navy 底 + 金 `#F0D691` 字"，所以**深色模式里会话名就是金色**。

## 安全不变量（每条都是踩过的坑）

1. 壁纸只存在于 `html::before/::after`：`z-index:-2/-1`、`pointer-events:none`——**永远在所有界面之下**，点击不可能落在皮肤上。
2. **不碰文档根与窗体**：`--dsw-specific-sidebar-fill` 同时是 Windows 窗体底色（`[data-windows-titlebar] .BynINW_frame`），一旦改成不透明值，**整个窗口会被它盖住、立绘几乎看不见**（这个坑踩过两次）。它现在是**全透明（0）**，不是"淡薄雾"——"薄"曾经是错的目标，0.30 仍然吃掉立绘两成亮度。这个 token 也绑在 `.BynINW_sidebarCol` 上，但**侧栏不受影响**：侧栏列由皮肤自有的 `--sk-panel`（0.86）以更高特异性覆盖，两条都由 `verify.mjs` 断言守住。**不要删掉这个键**——删了会让应用自己的不透明默认值回来。
3. 全项目不含 `-webkit-app-region`、无全局 `cursor`、无窗口级指针监听、无 `preventDefault`；只有一个被动 `keydown` 逃生快捷键。
4. 不用 `backdrop-filter`；不在应用容器上做 `transform`/`filter`。
5. `!important` 只允许出现在颜色/边框/阴影/令牌重绑定上（`verify.mjs` 强制）；令牌重绑定**必须限定在真正需要它的子树**——`ui-layout` 把主题 token 写成 `body` 的内联样式，所以整列重绑定会污染无关元素（曾把品牌徽标变成深字压深底）。
6. 生效后做**点击自检**：用 `elementFromPoint` 探测输入框与侧栏按钮，若回答探测点的是皮肤自身图层，或两次探测都只命中根元素，则**自动关闭皮肤**。7. **通栏选择器必须排除输入卡片**：对话区那条 `background:transparent!important` 的规则挂在 `[data-conversation-content]` 上，而**这个元素就是输入框的祖先**（hero 相位下输入卡片是它的后代）。卡片类名是 `<hash>_card`，会被 `[class*="_card"]` 子串命中，于是那条 `!important` 把应用给卡片上的底（`--dsw-specific-input-major`）和皮肤自己在卡片四角画的角标**一起抹掉了**——输入框等于没有背景。这个 bug 一直在，只是立绘够暗时"透明的卡片"看着也像深色底；**立绘一提亮就露馅**。现在选择器带 `:not([data-composer-card])`，并由 `verify.mjs`（静态）与 `cdp-verify.mjs`（实机读 `backgroundColor`）两边一起守。

8. **过程区不能上实底：`assistant-step` 不等于"答案"**（2026-10-09）。`[data-chat-flow-kind="assistant-step"]` 覆盖**每一步**——思考行、工具调用之间那些叙述行都是它；只有最终正文那一条额外带 `[data-turn-process-answer]`。按 kind 上实底，折叠状态下的过程行就变成一列**空 navy 小条**：应用把折叠掉的行标了 `hidden="until-found"`（UA 映射成 `content-visibility:hidden`，**藏内容、留盒子**），又不给它们自己的高度，于是皮肤那 12px 上下内边距成了唯一的高度来源——每行 24px、一个回合十几行就叠成**对话区正中一大块 300px 的空色板**。`not(:empty)` 拦不住：这些行在 DOM 里**非空**，只是内容不画。判别式只能用 **`data-turn-process-member="true"`**，它是两种折叠状态**都成立**的唯一标记（展开时 `hidden` 与 `data-turn-process-hidden` 都会摘掉，它还在）；同一排除也必须重复加在**光晕豁免**那条规则上，否则答案的豁免会把光晕从唯一还需要它的行上剥掉。由 `verify.mjs`（含反向断言）与 `cdp-verify.mjs` 两处守。
9. **字符串数组里的续行不能带逗号**。`CSS` 是由字符串数组 `join("")` 拼出来的，元素常写成一行的 `G + '…'` 加下一行的 `+ '…'` 续接。若在第一行末尾多写一个**数组逗号**，续接就不再属于这个表达式，而变成独立元素 `+ '…'`——**字符串前面加一元加号 = NaN**，编译出的选择器成了 `:is(…)NaNbackground-color:…`。这依然"有选择器、有声明块"，所以结构完整性检查看不见它：规则能解析、永不匹配、样式静默消失（2026-10-09 答案实底就是这么丢的）。现在 `verify.mjs` 直接断言产物里不出现 `NaN` / `undefined`。

## 验证工具

| 工具 | 作用 |
| --- | --- |
| `tools/verify.mjs` | 全部门禁（**99 项，0 失败才放行**）：安全 lint（层叠/指针/命中测试/根与窗体/`!important` 用途/重复声明/**规则结构完整性**/**产物里不得出现 `NaN`/`undefined`**）+ 假 DOM 冒烟（激活、面板渲染、逃生 API、自检三条判定路径、拆除）+ 设计断言（**零薄膜**、侧栏厚度、实底浮层、**配色谱系极性（40 个 token）**、纹章孪生、铭牌宿主、**空态已除 / 输入框沉底机制 / 提问与正文的实底范围（含"折叠过程行不得吃实底"）**、预览工具 token 副本无漂移） |
| `tools/mock-sidebar.mjs` | 把侧栏结构 + **真实 CSS**（从 `src/skin.js` 切片求值）+ DSH 的内联 token 写法渲染成 `art/_mock.html`（`--dark` 出深色版），页面内自带 computed-style 探针——**CSS 静默失效会显示成文字，而不是被当成设计问题**。纹章/饰带/铭文/分隔饰也由源码里同一批生成函数求值得到，绝不手抄。**它只渲染侧栏**，空态/输入框/对话流那部分它预览不了，只能实机验（见下） |
| `tools/cdp-verify.mjs` | **实机验证**——`verify.mjs` 的假 DOM 不渲染应用，所以凡是几何（空态是否真没了、输入框是否真在底部、立绘是否真变亮）它一条都验不了，这一趟才是那些改动的真门。要求 app 以 `--remote-debugging-port=9222` 启动（**单实例应用，必须先退出正在跑的实例**，否则第二个进程只会把第一个顶到前台、且不带端口）。它自己会：固定视口（否则 `background-size:cover` 会让两次截图不是同一批像素）、把 veil 归零、逐个把三层膜装回去拍"改前"、断言空态与输入框位置、走一遍对话流子树的绘制、展开思考折叠验证正文底色仍在（**答案在展开前按 `[data-turn-process-answer]` 认出来，展开后按 `data-chat-node-key` 找回来**——按"每个可见 assistant-step 都得有底"去验是错的，展开后多出来的那些本来就该是透明的） |
| `tools/sample-pixels.py` | 从**渲染出来的截图**量像素（PIL）。这是"零薄膜"的独立第二口径：`verify.mjs` 读的是 token **值**，它读的是窗口**实际画出来的像素**，两者可以不一致——token 对了但别处又盖了一层，正是立绘在"薄"值上暗了三版的原因。**看 `spread`（逐像素亮度的标准差），不要只看 luma**：亮色的膜是白的，摘掉它 luma 下降而立绘更艳，只读亮度会得出反向结论；膜无论什么颜色都只会压平动态范围 |
| `tools/legacy-entry.mjs` | 组合包迁移时把 profile patch 里**手写的老式 `- insert:` 块**摘掉（install / uninstall / verify 三处共用同一份删除算法）。当初这段逻辑在 install 里写错过一次：`continue` 会再自增一次，把内层扫描停住的那一行静默吃掉——profile patch 少一行 id 是最难从结果上看出来的破坏，所以现在有 9 条夹具断言盯着它 |


> 注意：**不要把 `url("data:...")` 写进 HTML 的 `style="..."` 属性**——双引号会截断属性，一个坏变量足以让整个多层 `background-image` 失效（mock 自检面板就是为此加的）。

`bak/` 不属于代码：它放改前的备份（`.bak-<时间戳>`，本项目不是 git 仓库，这是唯一的回退路径）与**已退役的一次性脚本**（`.retired-<日期>`）。跑过一次的字符串替换式迁移脚本不要留在 `tools/` 里——它们在下一次被顺手"修好"时就会真的重跑。
